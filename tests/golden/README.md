# Golden conformance fixtures

These fixtures define the byte-level behavior of the CAF version 2 and
version 3 file formats. They are the conformance contract for
`caf-format` and `caf-store`.

## Provenance

- The v2 vectors and store were generated by the Python implementation at
  commit `adc39ca` ("Add dev command to show info on a single content
  file"), CAF version 0.2.0, CPython 3.14, Linux. They remain unchanged so
  the Rust implementation stays compatible with existing stores.
- `generate_v3_vectors.py` is a standalone implementation of CAF v3. It
  uses Python's `hashlib` for SHAKE-128 and SHA3-256, plus the independent
  `blake3` package. The committed v3 vectors were generated with CPython
  3.14.4 and `blake3` 1.0.9 on Linux.
- The `caf-format` and `caf-store` golden integration tests validate the
  committed artifacts.

## Contents

- `vectors.json`: deterministic v2 file-format vectors. Every vector
  records the parent digest, content seed, file length, encoded 60-byte
  header, selected content slices, whole-file BLAKE2b-160 digest, and
  the expected store-relative path (`/`-separated). Cases cover:
  - a header-only file (60 bytes),
  - a single content byte,
  - a file ending exactly at the end of content block 0 (1 MiB),
  - a file containing the first byte of block 1 (1 MiB + 1),
  - multiple complete blocks (3 MiB),
  - a multi-block file ending mid-block.

  Every 1 MiB block boundary inside a vector file has a content slice
  straddling it, so both sides of the boundary are pinned.

  `metadata_vectors` pin the `.metadata/all` computation: BLAKE2b-160
  over the sorted chain-tip filenames concatenated as ASCII, stored as
  lowercase hex. This includes the zero-file-store case, whose chain
  tip is the 40-zero hex name.

- `vectors-v3.json`: deterministic v3 vectors generated by
  `generate_v3_vectors.py`. Each vector records the encoded header,
  selected content slices, all 32-byte leaf hashes, every Merkle reduction
  level, the tree root, the full 32-byte root, the truncated 20-byte file
  ID, and its relative path. Cases cover lengths 60, 61, 1 MiB,
  1 MiB + 1, 3 MiB, and 4 MiB + 1. The final two cases pin odd-child
  reduction at one and two successive levels.

- `generate_v3_vectors.py`: the independent CAF v3 reference generator.
  It imports no CAF code. To reproduce `vectors-v3.json` in a temporary
  environment:

      python3 -m venv /tmp/caf-v3-vectors
      /tmp/caf-v3-vectors/bin/pip install blake3==1.0.9
      /tmp/caf-v3-vectors/bin/python tests/golden/generate_v3_vectors.py

- `store/`: a small, real store produced by two `FileGenerator` runs
  (two chains: 3 files and 2 files, sizes 60/61/1024 and 4096/8192).
  It is committed as fixed binary data. Verifiers must accept it as a
  clean store; it also pins multi-chain `.metadata` layout.

## Verification

The committed bytes are the compatibility contract. Run the tests that
consume them with:

    cargo test -p caf-format --test golden --test golden_v3 --test golden_store
    cargo test -p caf-store --test golden_store
